ME-069 / legacy work item / volatile-knowledge mode

Add a pure two-clocks model: FSRS handles forgetting; volatile decision cards retire on obsolescence.

Chosen design: core owns JSON-safe lifecycle policy and queue eligibility over a caller-supplied now; API/state/persistence own project deck creation, TTL assignment, event invalidation, and source/deck retirement.

Quality System

Outcome: a project deck can produce review cards, then TTL or architecture-change invalidation removes those cards from scheduling.

Standards: pure kernel, Rust-only runtime, #27 API split respected, no hidden clocks in core, backward-compatible persisted snapshots.

Proof: core tests, API route test, live local request transcript, bun run ci, and bun run ci:full.

Acceptance

ADR documents two clocks, TTL cards, project decks, webhook/API retirement, promotion, and core exclusions.

Core exposes lifecycle types and filters expired/invalidated cards through pure passed-in time.

Verification

Claim: retired volatile cards stop scheduling. Falsifier: /review/next still returns the retired review unit after TTL/invalidation.

Driver: focused Rust tests plus a local API request replay written into the receipt.

Stop If

Stop if project deck behavior requires moving persistence, clocks, webhooks, HTTP, or source-specific triggers into memory-engine-core.

Stop if full CI exposes an unrelated dirty or infra failure that cannot be locally resolved without operator approval.

Change Shape

Docs: add docs/architecture/adr-002-volatile-knowledge-two-clocks.md.

Kernel: add lifecycle metadata to QueueCandidate and reference queue filtering behavior.

Boundary: persist lifecycle metadata and expose minimal v1 project deck create/invalidate routes in the #27 split crates.

Non-goals

No generic agent memory store, no external webhook runner, no production auth changes, no model-generated event classifiers, no core clock reads, no storage in core.
